# 现行实施阶段规划

## 1. 执行原则

- 每次只推进一个明确阶段；复杂阶段可拆成小批次。
- 固定流程为：实现 → 自动测试、lint、build → 用户实机验收 → 验收通过后提交。
- 每阶段开始前读取阶段规划和当时的权威规格；完成后先更新规划记录，再提交或进入下一阶段。
- Google Drive 现行设计与用户最新确认优先。不得自行修改数值、补充玩法或实现正式挑战模式。
- 阶段完成记录至少包含状态、实际内容、关键差异、自动检查、用户验收、提交哈希和遗留问题。

## 2. 阶段顺序

### 阶段 0：同步现行规格

只更新 `docs/00`～`06` 与 README，使四名角色、训练假人、万夫长及新版通则进入本地正式规格；不修改代码。

### 阶段 1：通用战斗引擎规则对齐

补齐战斗开始排序、完整生命周期、深度优先触发、持续时间、资源预留/支付、额外行动与回合、延迟队列、固定目标失效、死亡/结束截止、概率上限和固定 RNG 测试。不得提前实现流年或万夫长。

### 阶段 2：多单位战场与召唤机制

实现多敌方、登场排序、动态召唤/清除/暂退/恢复、即时回合、合法目标池、敌方位置、主体替换、伤害分摊入口、多单位死亡和胜利检查。使用通用测试单位验证，不塞入 Boss 专属判断。

### 阶段 3：第四名角色「势」流年

依次实现借势与借来势、风水流年、堪舆/定穴/势减半、三生流转、流与流转交换、生生流变、北山风起队列和最多三次固定目标释放、南阳水来，以及对应 UI 数据。

### 阶段 4：万夫长一阶段

实现骸骨将军、枪势、死躯、白骨银枪、群体攻击、能量、最多 5 名尸卒、召唤后即时回合，以及生命归零后的可靠转换入口。

### 阶段 5：万夫长二阶段与完整循环

实现万夫长暴击、战意无双、贪狼阈值、挑杀、破军枪术、两名不化王骑、近卫分摊、游骑枪术、冲阵、行动后固定顺序、三回合退场、跨阶段保存/清理及最终胜利。

### 阶段 6：Boss 阶段演出与战斗信息

实现 2 秒/1 秒转换演出、名称与卡片变化、血条增长/恢复、多敌方布局、召唤/协击/分摊/阈值/阶段事件、流年专属显示。演出锁定操作与推进，但不得改变结算顺序。

### 阶段 7：完整挑战性验收与平衡测试

覆盖四名单人及多人组合、站位决策、流年联动、尸卒压力、王骑击杀选择、连续额外行动、阶段切换和目标失效，排查必胜、必败和无限循环。平衡问题先记录，任何数值调整必须经用户确认。

## 3. 依赖与阶段边界

阶段必须按 `0 → 1 → 2 → 3 → 4 → 5 → 6 → 7` 推进。流年依赖阶段 1；万夫长依赖阶段 1 和 2；演出依赖完整 Boss 循环。每阶段补充相应回归测试，并确保王大海、严岩、李木头、训练假人及训练流程不被破坏。

## 4. 本轮明确非目标

正式挑战模式、角色养成/装备/稀有度/职业、未确认的新角色或 Boss、正式美术音频剧情，以及任何未经确认的玩法或数值均不进入本轮。
