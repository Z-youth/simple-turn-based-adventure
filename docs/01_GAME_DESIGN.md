# 《简单的回合制大冒险》测试版游戏设计基线


版本：V0 规格整理版
整理日期：2026-07-12


## 1. 文档用途


本文件用于把“第二游戏设计”中的原创草案转化为测试版开发时可直接引用的设计基线。它不替代用户的原创设计，也不允许开发者或 AI 擅自扩写关键玩法。


规则权威优先级：
1. 用户最新明确确认的设计与修改。
2. 《创意收集整理》中的原创内容。
3. 本文件及同目录其他测试版规格文件。
4. 《游戏设计建议》仅作风险提示与参考，不得覆盖原创设计。


若发现冲突、缺失或存在两种以上合理解释，必须暂停相关实现并询问用户，不得自行选择更“常见”的游戏规则。


## 2. 项目定位


项目名称：《简单的回合制大冒险》。
类型：原创角色驱动的回合制战斗游戏。
当前目标：制作浏览器可运行的完整训练模式测试版，用于验证行动、个人回合、行动序列、技能分支、资源循环、护盾、站位与角色联动。
开发优先级：功能正确与规则完整优先，玩法表现其次，正式美术与音频暂缓。


固定技术栈：React、TypeScript、Vite、普通 CSS。测试版不使用 Godot、后端或数据库。战斗核心逻辑必须与 React UI 分离，并保持数据驱动与可测试。


## 3. 完整游戏流程


初始界面
→ 模式选择
→ 角色选择
→ 站位编排
→ Boss 选择
→ 正式战斗
→ 训练统计或失败结果


### 3.1 初始界面
- 正上方显示《简单的回合制大冒险》。
- 提供“开始游戏”和“退出游戏”。
- 浏览器无法真正关闭页面时，“退出游戏”显示明确提示，不伪装为成功关闭。


### 3.2 模式选择
- 训练模式可用。
- 挑战模式显示“暂未开放”，不可进入。


### 3.3 角色选择与站位
- 训练模式可以选择当前已实现的全部角色。
- 队伍至少 1 名、最多 4 名角色。
- 同一队伍不能重复选择同一角色。
- 四个位置为：前1、前2、后1、后2。
- 四个位置均可独立留空，不强制前排先有人，也不自动调整位置。
- 前1对应后1，前2对应后2。
- 后排角色的对应前排存活时，该后排角色获得 50% 减伤；其他前排位置不能替代。


### 3.4 Boss 选择
- 一次选择 1 名 Boss。
- 当前测试版 Boss 为“训练假人”。


## 4. 战斗设计核心


### 4.1 行动序列
战斗使用全局“行动序列”。每个行动序列开始时读取所有存活单位的当前速度，按速度从高到低排序。单位依序获得个人回合；最后一个单位回合结束后，开始新的行动序列并重新排序。


### 4.2 行动与个人回合
- 行动：单位释放一次技能，特殊说明除外。
- 个人回合：单位在行动序列中获得的操作阶段。
- 默认一次行动后结束个人回合。
- 标注“不结束回合”或“同一回合可多次使用”的技能允许一回合多次行动。
- “行动时”“行动后”“回合开始”“回合结束”必须作为不同触发点实现。


### 4.3 技能分支
技能列出多个分支时，玩家在释放时选择一个分支；没有特殊说明时，所有多分支技能都遵循此规则。


## 5. 角色体系


角色分为「势」「意」「法」三个体系。


### 5.1 势
- 「势」是特殊 Buff，层数无上限。
- 每层提供 1 点攻击力。
- 通过「势」获得的攻击力加成上限为角色进入战斗时基础攻击力的两倍。
- 达到该攻击力加成上限后，在角色回合开始时按当前「势」生成「势压」。
- 每完整 10 层「势」获得 1 层「势压」。
- 「势压」在每个自身回合重新计算，回合结束时全部失去。
- 获得每层「势压」时获得 5 点护盾。
- 每层「势压」可在攻击时造成 3 点额外伤害，同一技能对同一目标最多触发一次。


### 5.2 意
- 「意」是特殊 Buff，层数无上限。
- 每个自身回合结束时失去 1 层。
- 持有至少 1 层时，暴击率增加 30%，不随层数重复增加。
- 持有时，每次行动后有 50% 概率获得 1 点能量。
- V0 暂无「意」角色，但引擎数据模型应能扩展。


### 5.3 法
- 「法」是无上限的特殊能量，本身没有被动效果。
- 「法」体系角色可消耗「法」强化技能。
- V0 暂无「法」角色，但引擎数据模型应能扩展。


## 6. V0 可玩内容


可选角色：王大海、严岩。
可选 Boss：训练假人。
可玩模式：训练模式。


测试重点：
- 王大海的连续行动、起势、海潮与自动技能循环。
- 严岩的受击获得「势」、资源转盾、全队护盾与护盾值伤害。
- 前后排保护是否有实际战术意义。
- 多段攻击、额外伤害、状态计时和复杂触发链是否稳定。


## 7. 设计边界


V0 不制作挑战模式、养成、装备、剧情、正式角色美术、正式动画和正式音频。


当前未出现的机制，例如复活、召唤物、额外回合、追击、反击、协同攻击、闪避、命中、控制和负能量角色，可以预留合理扩展点，但不得为了未来需求提前建设庞大系统。


## 8. 开发原则


- 玩法文字的明确含义优先于程序员习惯。
- 特殊规则覆盖通用规则。
- 一个技能可以包含多次攻击，技能、行动、攻击和伤害事件必须分层建模。
- 每项关键规则都应有自动测试或明确的人工验收步骤。
- Codex 每阶段只完成明确范围，运行测试、lint 与 build 后汇报，不自动提交 Git。
